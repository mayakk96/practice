Fictional educational incident response runbook. Start with the observable symptom, affected transaction IDs, business date and currency. Review API errors, latency percentiles, network failures, pending outbox count, oldest event age and consumer lag. Correlate safe structured logs using the request ID rather than customer names or account details. Classify a root cause only after validating evidence; distinguish a hypothesis from a confirmed finding. Protect financial integrity before restoring throughput. For a network outage reduce new load and investigate retry amplification instead of increasing retries indefinitely. For delayed events restore the broker and monitor ordered outbox recovery. Preserve audit records, identify remediation owners and record resolution notes. Follow up with targeted tests and alert tuning. This repository's SLOs are illustrative targets, not production guarantees. An AI explanation is read-only evidence assistance and never an authorization to change financial state.
