Fictional educational transaction lifecycle policy. A transaction is a synthetic instruction with a positive amount in integer minor units and a single explicit currency. Validation checks the source account, currency and duplicate references. Authorization asks the fictional network whether an instruction is accepted; authorization alone does not post a captured purchase. Capture records a balanced journal pair. Clearing confirms transaction details before final settlement. Settlement confirmation records the payable-to-cash movement. State transitions are explicit, audited and constrained; operators cannot arbitrarily set statuses. Never delete a settled transaction. A reversal compensates an eligible authorization or captured instruction. A refund creates a separate linked credit after settlement. This demonstration supports one full refund rather than partial refunds. Human operators authorize all financial commands through the secured REST API; model-facing tools only read evidence.
