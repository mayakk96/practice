Fictional educational distributed systems policy, version 1.

Idempotency means repeating the same logical request does not cause additional business effects. Case creation may include an Idempotency-Key. The same key and request payload return the original case; reusing the key with different content is a conflict. A unique database constraint and a transaction coordinate concurrent attempts across application instances. Outbox events are written in the same transaction as case changes. A background dispatcher publishes them to Kafka using case identifier as the partition key. Publishing and marking an event delivered are not one atomic transaction, so duplicate messages are possible. Consumers must deduplicate using the event identifier and commit their database work before acknowledging the Kafka record.
